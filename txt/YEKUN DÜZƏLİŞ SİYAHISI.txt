1. ComplaintType hardcoded validasiyası – funksional ölüm

    Fayl: app/Http/Requests/ComplaintStoreRequest.php və ComplaintUpdateRequest.php

    Problem: 'complaint_type' => 'nullable|in:qezali,nasazliq,texniki_xidmet' – yeni tip əlavə etsən, heç vaxt valid olmayacaq.

    Risk: İstifadəçi admin paneldən tip yaradır, amma həmin tiplə şikayət açmaq mümkün deyil. Əsas funksionallıq sınır.

    Həll: 'complaint_type' => 'nullable|exists:complaint_types,name' ilə əvəz et. (İstersən, complaint_type_id foreign key istifadə edərək daha təmiz modelə keçə bilərsən, amma bu addım üçün sadə exists kifayətdir).

    Test: Yeni tip yarat, həmin tiplə şikayət aç – keçməlidir.

2. bus rolu – qeydiyyatın çökməsi

    Fayl: app/Http/Controllers/Auth/RegisteredUserController.php

    Problem: 'role' => 'bus' – RoleEnum-də bus yoxdur. DB constraint də buna icazə vermir.

    Risk: İstifadəçi qeydiyyatdan keçə bilmir → 500 error.

    Həll: 'role' => RoleEnum::VIEWER->value (və ya 'user') ilə dəyiş. Hazırda bu controller artıq abort(403) edir, amma əgər gələcəkdə açılsa, xəta qalmasın.

    Test: Qeydiyyat səhifəsinə daxil ol (əgər açıqdırsa) və yeni istifadəçi yarat – uğurlu olmalıdır.

3. Warehouse import – soft-delete məlumatların bərpa olunmaması

    Fayl: app/Imports/WarehouseImport.php

    Problem: Warehouse::withoutGlobalScopes()->where('code', $code)... – soft-delete olmuş detalları tapır, amma restore() etmir. Nəticədə update işləyir, amma model deleted_at null olmadığı üçün sistemdə görünməz qalır.

    Risk: İdxal zamanı məlumatlar itirilir və ya ikiqat yaranır.

    Həll: if ($warehouse && $warehouse->trashed()) { $warehouse->restore(); } əlavə et. Həmçinin ->withTrashed() istifadə etməyə ehtiyac yoxdur, çünki withoutGlobalScopes artıq bütün qeydləri gətirir.

    Test: Bir detalları sil, sonra həmin kodu ehtiva edən Excel yüklə – detal bərpa olunub görünməlidir.

4. Queue import-larında session() fallback – importların çökməsi

    Fayl: Bütün Import class-ları (BusesImport, ComplaintsImport, WarehouseImport, DriversImport, EmployeesImport, BusDailyStatusesImport, DailyKmRecordsImport).

    Problem: Konstruktorda $this->garageId ??= (int) session('current_garage_id'); – queue worker-da session olmadığı üçün null olur və import ya çökür, ya da garage_id-siz yazılır.

    Risk: Bütün Excel idxal əməliyyatları qeyri-müəyyən nəticə verir.

    Həll:

        Parametrləri məcburi et: public function __construct(public int $garageId, public ?int $companyId = null)

        session() fallback-lərini tamamilə sil.

        Controller-lərdə artıq düzgün ötürülür – yalnız import siniflərini təmizlə.

    Test: Queue worker işə sal, Excel idxal et – garage_id düzgün yazılmalıdır.

5. Excel import-da per-row transaction – performans qətli

    Fayl: ComplaintsImport.php, WarehouseImport.php (və bəlkə başqaları)

    Problem: onRow metodunun daxilində DB::transaction(...) – hər sətir üçün ayrıca transaction. 5000 sətir → 5000 transaction, serveri yavaşladır.

    Risk: Böyük fayllarda timeout və ya resurs tükənməsi.

    Həll: DB::transaction bloklarını tamamilə çıxar. WithChunkReading artıq hər chunk-ı avtomatik transaction-a alır.

    Test: 5000+ sətirli Excel yüklə – müddət əhəmiyyətli dərəcədə azalmalıdır.

7. Super Admin və Garage Admin qarışıqlığı

    Fayl: app/Models/User.php (isSuperAdmin() metodu)

    Problem: role === 'admin' də super admin sayılır. Halbuki garage_user.role = admin qaraj adminidir. Bu, authorization qarışıqlığı yaradır.

    Risk: İstifadəçilərə gözlənilməz icazələr verilə bilər.

    Həll: super_admin ayrıca rol olaraq saxlanılsın, admin yalnız garage səviyyəsində işlədilsin. isSuperAdmin() yalnız role === 'super_admin' yoxlasın.

    Test: admin rolundakı istifadəçi başqa qarajın məlumatlarına baxa bilməməlidir.

8. GarageContext – static state təhlükəsi

    Fayl: app/Services/GarageContext.php

    Problem: Context istifadə olunsa da, bəzi yerlərdə hələ session-a müraciət var. Həmçinin HasGarageScope yalnız GarageContext::has() olduqda işləyir – kontekst yoxdursa, heç bir filter tətbiq olunmur.

    Risk: CLI, queue və ya xarici sorğularda məlumat sızması.

    Həll:

        HasGarageScope-də GarageContext::has() şərtini çıxar – həmişə tətbiq et (əgər context yoxdursa, defolt olaraq null qaytarsın və ya xəta versin).

        Bütün sorğularda garage_id mütləq ötürülsün.

    Test: Context olmadan model query çağır – filter tətbiq olunmalıdır.

9. Complaint update – stock diff optimallaşdırılması
